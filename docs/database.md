# Users Database Schema

## Authentication Users

The primary user identity table is `authentication_users`.

### Identity

- `id`: internal unsigned `BIGINT` primary key for relational integrity.
- `uuid`: public stable identity, generated by Prisma with `uuid()`, stored as `CHAR(36)`, and protected by a unique constraint.

The internal numeric key is intentionally separated from the public UUID so external service contracts do not expose database sequencing.

### Account identifiers

- `username`: optional, unique, maximum 100 characters.
- `email`: optional, unique, maximum 191 characters.
- `phone`: optional, unique, maximum 30 characters.

MySQL permits multiple `NULL` values on these unique columns, which allows an account to be created with only the identifiers that are currently available.

### Account state

- `status`: application state placeholder, defaulting to `pending`.
- `is_active`: active/inactive flag, default `true`.
- `is_verified`: verification state, default `false`.

The domain layer will define the authoritative status/invariant rules in Step 06.

### Timestamps and soft delete

- `created_at`: creation timestamp.
- `updated_at`: automatically maintained update timestamp.
- `deleted_at`: nullable soft-delete timestamp.

Normal application queries must exclude rows where `deleted_at IS NOT NULL`. Physical deletion is intentionally outside the normal user lifecycle.

### Index strategy

The table has indexes for:

- `status`
- `is_active`
- `deleted_at`
- `(status, deleted_at)`
- `(is_active, deleted_at)`

The composite indexes support the expected active/non-deleted filtering pattern without coupling the schema to a specific repository implementation.

### Scope

This step defines and validates the Users schema boundary only. Prisma migration/repository implementation is handled in Step 05.
